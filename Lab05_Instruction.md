# Лабораторная 5 — наследование и проектирование кода

ЛР5 меняет структуру программы. Пользовательские возможности прежние:
`--task 1` — формула варианта 14; `--task 2` — пересечение дат и рекурсивная
сумма варианта 7; `--task 3` — сравнение строк и проверки email, телефона, IP.
Отдельного режима `--task 5` нет: по ТЗ нужно переработать существующие задания.

## Что изменилось

- `src/Labs/Tasks/LabTask.cs` — новый абстрактный базовый класс. Задаёт метод
  `Execute()`, общий формат числового результата и обработку исключений проверок.
- `src/Labs/Tasks/FormulaTask.cs`, `DateIntersectionTask.cs`, `StringCheckTask.cs` —
  новые классы-наследники. Принимают готовые `int`, `DateTime`, `string` через
  конструкторы и возвращают строки результата. Не читают аргументы и не работают
  с консолью. В `Program` запускаются через общий тип `LabTask` — это полиморфизм.
- `Task1Calculator.cs`, `Task2Calculator.cs`, `Task3StringChecker.cs` перенесены
  из `Tasks` в `src/Labs/Calculations/` с новым пространством имён
  `Labs.Calculations`. В них остались только вычисления и проверки.
- `src/Labs/Utils/CmdArgsParser.cs` — по-прежнему читает аргументы и преобразует
  их в нужные типы. Теперь использует собственное исключение `InputException`.
- `src/Labs/Utils/InputException.cs` — новый класс исключения для ошибок ввода.
  `ValidationException` из ЛР4 сохранён для ошибок расчёта и проверок строк.
  Текст пояснения хранится в унаследованном свойстве `Message`.
- `src/Labs/Utils/ConsoleOutput.cs` — вывод готового текста и ошибок, без ссылок
  на задания и калькуляторы.
- `src/Labs/HelpText.cs` — новое место для описания режимов программы и справки.
- `src/Labs/Program.cs` — в `Main` выбирается задание через `switch`, создаётся
  объект с типизированными параметрами, вызывается `Execute()`, выводятся
  результаты. Здесь же обрабатываются ошибки ввода и валидации.

Путь данных: аргументы → `CmdArgsParser` → типизированные значения → наследник
`LabTask` → калькулятор/проверки → готовые строки → `ConsoleOutput`.

## Сборка и запуск на Windows

Нужен .NET 10 SDK. Все команды выполнять в PowerShell из корня репозитория.

```powershell
git checkout develop
git pull --ff-only
dotnet build src\Labs
```

Пример запуска:

```powershell
.\src\Labs\bin\Debug\net10.0\Labs.exe --task 3 -s1 abc -s2 cba
```

Будет 9 строк результатов: `EQUAL: FALSE`, `NORMALIZED: FALSE`,
`REVERSED: TRUE` и шесть проверок типов со значением `FALSE`.
Без аргументов программа выводит справку.

## Встроенные тесты

Отдельного скрипта ЛР5 в репозитории нет. Проверить сохранение прежних возможностей:

```powershell
powershell -ExecutionPolicy Bypass -File src\UAT.Labs\RunCheckLab01.ps1 -Variant 14
powershell -ExecutionPolicy Bypass -File src\UAT.Labs\RunCheckLab02.ps1 -Variant 7
powershell -ExecutionPolicy Bypass -File src\UAT.Labs\RunCheckLab03.ps1
```

Ожидаемый итог: `ERR: 0`, `WARN: 0` во всех трёх запусках.
`-ExecutionPolicy Bypass` действует только на запускаемый процесс PowerShell.

Проверка структуры ЛР5 производится по коду: есть `LabTask`, три наследника,
отдельные калькуляторы, независимые утилиты ввода/вывода и свои исключения.

Проект `src/Labs.Tests` пока содержит только исходный тест-заглушку.
Команда `dotnet test src\Labs.Tests` не заменяет три проверки выше.

## Проверка при разработке

На Mac доступны SDK .NET 6 и 7, PowerShell отсутствует. Поэтому для проверки
собраны временные копии старой и новой версии под .NET 7; в репозитории сохранён
целевой `net10.0`. Вывод сравнивался с ЛР4 на примерах штатных скриптов и CSV
нужных вариантов, а также на дополнительных граничных случаях. Отдельно
проверены наследование, полиморфизм, исключения, отсутствие вывода из заданий
и форматирование результата при русской локали. Штатные PowerShell-скрипты
и сборка под .NET 10 на этом Mac не запускались.
